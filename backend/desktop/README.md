# ARAM Native Windows Desktop Pilot — UNRELEASED

**This is an early, native Windows desktop window, not the finished financial-statement application, not a website in a webview and not a released or approved accounting tool.**

## Actual supported features (all read-only)

- Native Python **Tkinter/ttk** Persian desktop window. Three functional notebook tabs: validation, financial-workflow limitations and help.
- Five implemented native menu actions: **File → Choose XLSX (Ctrl+O); Run preflight (Ctrl+R); Clear selection (Ctrl+L); Exit (Ctrl+Q); Help → About (F1)**.
- Three native buttons are alternate handles for Choose XLSX, Run preflight and Clear selection. Run preflight is **disabled** before choosing an eligible file. Canceling the picker does not discard an existing selection.
- Uses the existing authoritative `aram_backend.pilot_workbook.preflight_pilot_workbook` in memory to display all reported issue counts and the first 3,000 issue details with sheet, row, field and error code. Warns if more than 3,000, rather than silently hiding them.
- Accepts a local existing regular `.xlsx` file up to **20 MiB**, rejects symlinks and malformed/nonexistent paths; bounds XLSX ZIP metadata to 500 entries and **128 MiB uncompressed** before openpyxl processing. Does not import workbook rows, connect to SQL, post ledger entries, alter files, upload data, sign decisions, or generate financial statements.
- A passing format preflight is **NOT proof of accounting truth**, completed mapping, approved notes/subnotes, approval, reconciliation, statement correctness or authorization to export/print. All those workflows are explicitly marked **not implemented**, without dead buttons.

## Run from source on Windows 10/11 (Python 3.12 x64)

Install a trusted 64-bit Python 3.12 distribution with Tcl/Tk. In PowerShell from the repository root:

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest tests/test_desktop_pilot.py
python -m aram_backend.desktop_pilot
```

No SQL Server or FastAPI HTTP server needs to run for **this isolated preflight pilot**. That does **not** mean the eventual full financial application will not require a secure database or service architecture.

## Build the unsigned Windows EXE

```powershell
cd backend
python -m pip install "pyinstaller>=6.10,<7"
.\desktop\build_windows_exe.ps1
.\dist\AramPilot-UNRELEASED.exe
```

The script uses native Windows PyInstaller to create **`backend/dist/AramPilot-UNRELEASED.exe`** as a one-file, windowed application. It does not build an MSI, add an installer wizard, sign the binary, create a production release or modify the accepted Git branch. You must build on Windows for a Windows EXE; compiling on Linux is not equivalent.

The dedicated `.github/workflows/desktop-windows-ci.yml` builds this same unsigned file on GitHub's Windows x64 runner for Draft PRs, runs Python tests, verifies `--self-test` and **programmatic Tk native menu/button/tab invocation** `--ui-smoke`, then attaches a short-retention **UNRELEASED** Actions artifact for inspection. An artifact is **not an approved release**. Windows SmartScreen warnings may appear for unsigned builds; do not bypass organizational security controls to execute it.

## Automation boundaries and what has NOT been tested

- `python -m aram_backend.desktop_pilot --self-test` is a **headless** smoke of the imported app/controller and rejection of invalid XLSX.
- `python -m aram_backend.desktop_pilot --ui-smoke` invokes **real Tk menu/button callbacks** and traverses all existing tabs on a synthetic workbook. It does not click physical pixels, test real financial user data, or attest to desktop accessibility or layout across machines.
- **Full mouse and keyboard GUI E2E** (Windows clean VM, 100% physical hit-target traversal, Microsoft UI Automation, accessibility, scaling 100/150/200%, focus order, error messages, I/O race and protected financial workflows) is **not yet verified**. User's original all-buttons request cannot be called complete merely because this small shell passes its current smoke.
- One-file PyInstaller dependencies are not signed, pinned to exact hashes or audited for enterprise deployment. An external security and license compliance review is required.
- Source data is never copied into the repository, GitHub artifacts or test fixtures. The synthetic XLSX generated by the smoke test is disposed of after the run.
