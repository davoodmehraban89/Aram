# راهنمای شناسایی ساختار پایگاه داده پیوست برای آرام

این بسته فقط ابزار کمکی DBA برای شناسایی **فراداده** است؛ اتصال‌دهنده محصول نیست. فایل [aram-payvast-schema-discovery.sql](./payvast-schema-discovery.sql) فقط شامل پرس‌وجوهای `SELECT` از فراداده SQL Server است و هیچ ردیف عملیاتی یا مالی را نمی‌خواند.

**وضعیت بررسی:** فقط بازبینی ایستای محتوا و نحو انجام شده است. فایل روی SQL Server، محیط آزمایشی یا پایگاه داده مشتری اجرا نشده؛ صحت اجرا، کامل‌بودن خروجی، سطح دسترسی و سازگاری با نصب واقعی مشتری تأیید نشده است.

## روش استفاده توسط DBA

1. با هویت فقط‌خواندنیِ مورد تأیید مشتری به SQL Server متصل شوید. نام کاربری، رمز عبور، رشته اتصال، توکن یا کلید را در این بسته، مخزن یا خروجی قابل اشتراک قرار ندهید. تنظیم امن اتصال زنده موضوع مرحله بعد است.
2. پایگاه داده موردنظر پیوست را در فهرست انتخاب پایگاه داده SSMS انتخاب کنید. اسکریپت پایگاه داده را تغییر نمی‌دهد؛ در خود فایل هیچ فرمان تعویض پایگاه داده وجود ندارد.
3. متن فایل را بازبینی کنید و در همان پایگاه داده انتخاب‌شده اجرا کنید. اسکریپت هیچ داده، شیء، مجوز یا تنظیمی را تغییر نمی‌دهد و از SQL پویا استفاده نمی‌کند.
4. نتیجه بخش دوم را با پایگاه داده موردنظر تطبیق دهید. شش مجموعه نتیجه را با شماره بخش و زمان اجرای UTC ذخیره کنید؛ این زمان صرفاً زمان شناسایی ساختار است، نه زمان یک snapshot مالی.
5. پیش از اشتراک‌گذاری، نام پایگاه داده و نام‌های قابل شناسایی مشتری را در صورت نیاز حذف یا با برچسب‌های ثابت جایگزین کنید. جایگزینی یک نام باید در تمام بخش‌ها یکسان باشد تا ارتباط‌ها قابل بررسی بمانند. هیچ داده مالی یا نمونه ردیف عملیاتی به این بسته اضافه نکنید.

## خروجی‌ها چه چیزی را نشان می‌دهند؟

| بخش | محتوای خروجی |
| --- | --- |
| ۱ | نسخه و ویرایش موتور SQL Server گزارش‌شده توسط همان اتصال |
| ۲ | نام و شناسه پایگاه داده جاری، سطح سازگاری و collation |
| ۳ | جدول‌ها و نماهای کاربریِ قابل مشاهده، همراه schema |
| ۴ | نام و ترتیب ستون‌ها، نوع اعلام‌شده و نوع پایه، طول بر حسب بایت، precision، scale، امکان NULL و مشخصات identity/computed |
| ۵ | ستون‌های کلیدهای اصلی و یکتا و سایر ایندکس‌های یکتا به ترتیب کلید؛ پرچم‌ها تفاوت constraint، ایندکس فیلترشده، غیرفعال یا فرضی را مشخص می‌کنند |
| ۶ | فقط رابطه‌های FK اعلام‌شده و جفت ستون‌های آن‌ها؛ همراه وضعیت غیرفعال/نامطمئن و رفتار مرجع |

نمایش فراداده به مجوز همان هویت بستگی دارد. **خروجی خالی یا ناقص، نبودن جدول، ستون، کلید یا رابطه را ثابت نمی‌کند.** محدودیت دسترسی یا خطای مشاهده‌شده را همراه نتیجه ثبت کنید؛ این فایل سطح دسترسی را افزایش نمی‌دهد. مقدار `NULL` در برخی ویژگی‌های موتور نیز ممکن است ناشی از پشتیبانی‌نشدن آن ویژگی یا محدودیت محیط باشد.

وجود ایندکس یکتا به‌تنهایی برای تعیین شناسه پایدار منبع کافی نیست؛ فیلتر، وضعیت و تعریف واقعی آن باید بررسی شود. نبود FK قابل مشاهده نیز مجوز حدس‌زدن ارتباط از روی شباهت نام ستون‌ها نیست. این خروجی‌ها معنای حسابداری، تفکیک شرکت/سال، وضعیت سند، واحد پول یا قواعد نگاشت را مشخص نمی‌کنند.

## اطلاعات تکمیلی موردنیاز

نسخه دقیق نرم‌افزار پیوست، مستند رسمی schema یا رابط خواندن پشتیبانی‌شده، تعریف شرکت و سال مالی، معنای سطوح حساب و تفصیلی، کلید پایدار رکورد و روش استخراج سازگار باید از مشتری یا پشتیبانی پیوست دریافت شود. جزئیات بیشتر در [یادداشت الزامات](../superpowers/specs/2026-10-23-payvast-governed-mapping-design.md) آمده است. هیچ نام جدول یا ستون اختصاصی پیوست در این بسته فرض نشده است.

مبنای مستندات، Microsoft SQL Server است: [SERVERPROPERTY](https://learn.microsoft.com/en-us/sql/t-sql/functions/serverproperty-transact-sql)، [sys.columns و اتصال به sys.types](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-columns-transact-sql) و [محدودیت نمایش فراداده](https://learn.microsoft.com/en-us/sql/relational-databases/security/metadata-visibility-configuration). هدف نحوی فایل SQL Server 2019/2022 است؛ این هدف جای تأیید روی نسخه واقعی مشتری را نمی‌گیرد.
